## 1. 배경 및 문제 정의

### 1.1 문제

여행지를 고를 때 사람들은 자신이 원하는 분위기를 말로 설명하기 어렵다. "조용하고 자연스러운 느낌" 같은 감각적인 취향은 검색어로 표현이 안 된다. 기존 여행 플랫폼(네이버 지도, 트립어드바이저, 마이리얼트립 등)은 인기순·마케팅 중심으로 결과를 노출하기 때문에 취향이 반영된 결과를 얻기 어렵다.

### 1.2 핵심 인사이트

- 사람들은 말보다 **사진**으로 자신의 취향을 더 쉽게 표현할 수 있다
- 사진을 고르는 행동만으로 AI가 취향을 분석할 수 있다
- 분위기 기반 추천 → 지역 클러스터 → 1박 2일 코스로 이어지는 플로우가 여행 계획의 전체 여정을 커버한다

---

## 2. 제품 개요

**SAIRO**는 사진 선택만으로 여행 취향을 분석하고, 분위기에 맞는 국내 여행지와 1박 2일 코스를 추천하는 모바일 앱이다.

### 2.1 포지셔닝

| 구분 | 기존 플랫폼 | SAIRO |
|------|-----------|-------|
| 탐색 방식 | 키워드 검색 | 사진 선택 |
| 추천 기준 | 인기도·마케팅 | AI 취향 분석 |
| 추천 카드 단위 | 개별 장소 | 지역 |
| 최종 여행 계획 | 직접 구성 | 1박 2일 코스 자동 구성 |
| 회원가입 | 필요 | 불필요 |

---

## 3. 목표 사용자

**주말 1박 2일 여행을 계획하고 있지만, 자신의 취향을 검색어로 표현하기 어려운 사용자**

### 페르소나

- 20–30대 직장인
- 주말 짧은 여행을 자주 가지만 매번 어디 가야 할지 고민
- "조용한 카페 분위기" "자연 속 힐링" 같은 감각적 선호는 있지만 검색창에 뭘 쳐야 할지 모름
- SNS에서 사진으로 장소를 발견하는 데 익숙함
- 주로 금요일 저녁~토요일 아침에 급하게 다음 주말 여행을 계획하며, 블로그·SNS를 오가다 정보 과부하로 결정을 미룬 경험이 있다

## 4. MVP 범위

### 4.1 In Scope

| 기능 | 사용자 관점 설명 |
|------|----------------|
| 취향 분석 | 40장 사진 중 마음에 드는 것 5~10장 선택 → AI가 취향을 분석하고 무드 태그 도출 |
| 여행지 추천 | 취향과 어울리는 국내 여행지를 지역 단위로 추천 |
| 1박 2일 코스 | 추천 지역별로 1박 2일 코스 제공 |
| 주변 장소 | 코스 관광지 주변의 식당·숙박·카페를 함께 제공 → [ADR 0016](./decisions/0016-self-built-course-with-nearby-places.md) |
| 장소 상세 | 운영시간, 휴무일, 주차 여부, 연락처 (서버 API 제공, 클라이언트 상세 화면 구현 범위는 별도 결정) |
| 코스 저장 | 내 기기에서 저장한 코스 이력 조회 |
| 코스 공유 | 코스를 링크로 공유, 수신자가 앱으로 바로 확인 |
| 다시 추천받기 | 새로운 취향 분석 재실행 |

### 4.2 Out of Scope (v1)

- 회원가입 / 소셜 로그인
- 실시간 예약 연동
- 리뷰·평점 기능
- 지도 탐색 (핀 표시는 포함, 탐색 UI 제외)
- 개별 스팟 북마크 (코스 단위 저장만 지원)

> **2026-08-05.** "코스 스팟 주변 카페·식당 자동 보완"을 이 목록에서 뺐다.
> 2026-08-03 2차 회의에서 주변 장소 제공(B안)이 확정돼 **In Scope로 바뀌었다.**
> → §4.1, [ADR 0016](./decisions/0016-self-built-course-with-nearby-places.md)

## 5. 사용자 플로우

### 5.1 메인 플로우

```
[1] 랜딩 화면
     ↓ "취향 분석 시작하기"
[2] 온보딩 — 40장 사진 스와이프, 5~10장 선택
     ↓ "분석하기"
[3] 취향 분석 결과 + 무드 태그 표시
     ↓
[4] 추천 여행지 목록 (지역별 그룹핑, 썸네일 포함)
     ↓ 지역 카드 탭
[5] 해당 지역 스팟 목록 + 지도 핀
     ↓ "코스 보기"
[6] 1박 2일 코스 (Day 1 / Day 2) + 주변 식당·숙박·카페
     ↓ 스팟 탭
[7] 장소 상세 (이미지, 운영시간, 주차, 연락처)
```

### 5.2 공유 플로우

```
[코스 화면] "공유하기" 탭
     ↓ 서버가 공유 스냅샷 저장 → 링크 발급
[클라이언트] OS 공유 시트로 링크 전달
             (카카오톡, 문자, 클립보드 등)
     ↓
[수신자] 링크 탭
     → 앱 설치 시: 앱 내 공유 코스 화면으로 바로 이동
     → 앱 미설치 시: 앱스토어로 이동
[공유 코스 화면] 공유 당시 스냅샷 표시 (읽기 전용)
```

- 공유 링크는 앱 설치 여부와 관계없이 자연스럽게 연결된다 (도메인 미정 — §12 참조)
- 공유 화면은 편집·삭제 없이 읽기 전용

### 5.3 핵심 UX 원칙

**선택 단계 정보 은닉** *(제품 목표)*

온보딩 사진 선택 화면에서 장소명·지역명을 일절 노출하지 않는다. 추천 결과 화면에서 처음으로 지역을 공개한다. 사용자가 "어디인지"가 아닌 "분위기"로만 선택하게 하는 것이 핵심 UX 원칙이다.

| 항목 | 내용 |
|------|------|

| 항목 | 내용 |
|------|------|
| 노출 수량 | 매 세션 40장 랜덤 |
| 선정 기준 | 수상작 기준 품질 필터링으로 구성된 풀에서 추출 |
| 선택 조건 | 최소 5장·최대 10장 |
| 이미지 표시 | 모든 사진은 동일한 비율로 노출되어 분위기에만 집중할 수 있도록 한다 |

## 7. 추천 방식

### 7.1 취향 분석

사용자가 선택한 사진들로부터 AI가 취향 프로필을 생성한다. 선택한 사진의 분위기를 종합해 **무드 태그** (최대 5개)와 **한 줄 요약**을 도출한다.

### 7.2 여행지 추천

취향 프로필과 DB 사진의 분위기 유사도를 계산해 가장 어울리는 지역을 추천한다.

- 추천 단위는 **지역** (같은 지역이 중복 노출되지 않음)
- 목표 응답 시간: **3초 이내**

## 8. 코스 데이터

**코스는 자체 `spots` 데이터로 만든다.** 관광공사가 편집한 큐레이션 코스를 그대로 가져오지 않는다.
사진 임베딩으로 뽑은 지역에 맞춰 우리가 코스를 구성한다.
→ [ADR 0016](./decisions/0016-self-built-course-with-nearby-places.md)

| 항목 | 내용 |
|------|------|
| 코스 구성 | Day 1 / Day 2 분리, 1박 2일 고정 |
| 코스 원천 | 자체 `spots` 테이블 + greedy nearest-neighbor 정렬 ([ADR 0008](./decisions/0008-greedy-nearest-neighbor-course-sort.md)) |
| 스팟 정보 | 운영시간, 휴무일, 주차, 연락처, 지도 좌표 |
| 주변 장소 | 코스 관광지 주변의 식당·숙박·카페를 TourAPI로 조회해 덧붙인다 |
| 지원 지역 | 장소가 확보된 지역. 한 지역에 장소가 2개 이상일 때만 코스로 만든다 |

지역당 코스 수와 지역별 장소 수는 아직 제품 기준으로 확정되지 않았다.
→ [Q-05, Q-08](./open-questions.md)

## 11. 주요 제약 및 리스크

| 리스크 | 내용 | 대응 |
|--------|------|------|
| 외부 관광 데이터 불안정 | 장애 시 코스 데이터 없음 | 빈 응답 반환, 클라이언트 오류 안내 |
| 사진 외부 URL 의존 | 이미지 서버 장애·모바일 보안 제한 | 배포 전 자체 스토리지 이전 검토 |
| 사진 저작권 | 관광공모전 수상작·공사 사진 사용 | 문제 없음 확인 |
| 좌표 누락 | 일부 스팟 위치 정보 없음 | 외부 데이터로 보완, 없으면 지도 핀 미표시 |
| 기기 ID 분실 | 앱 재설치 시 이력 초기화 | 의도된 동작으로 허용 |
| 공유 코스 누적 | MVP는 만료·정리가 없어 `courses`와 `shared_courses`가 계속 쌓임 | 볼륨 증가 시 30일 기준 재검토 (§12 #3, [ADR 0014](./decisions/0014-share-link-lifetime.md)) |

## 12. 미결 사항

구현 수준의 미결 사항은 `docs/open-questions.md`에서 관리한다. 여기서는 제품 결정에 영향을 주는 항목만 기록하고 관련 문서를 함께 표시한다. 확정되기 전에는 Q 번호를, 확정된 뒤에는 그 결정을 담은 문서를 가리킨다.

| # | 항목 | 상태 | 관련 |
|---|------|------|------|
| 1 | 무드 태그 라벨 목록 | ✅ 자연·바다·역사·도시·힐링·계절·체험 7개로 잠정 합의, 운영 후 재검토 | — |
| 2 | 추천 여행지 수 | 🔲 유사도 임계값 결정 선행 필요, 추천 결과 확인 후 결정 | Q-08 |
| 3 | 공유 링크 만료 기간 | ✅ MVP는 무기한, 볼륨 증가 시 30일 기준 재검토 | [ADR 0014](./decisions/0014-share-link-lifetime.md) |
| 4 | 서비스 도메인 | 🔲 미정 (공유 링크·딥링크·앱 스토어 연동에 필요) | — |
| 5 | 성공 지표 목표치 | 🔲 완료율·저장율·공유율 목표 수치 미정 | — |

**#4에 Q 번호가 없는 것은 누락이 아니다.** 서비스 도메인은 구현 수준의 미결이 아니라
제품·운영 결정이라 여기서만 관리한다. 구현이 도메인 값에 의존하게 되면 그때 Q 항목을 만든다.
