# 아키텍처 결정 기록 (ADR)

되돌리기 어려운 결정과 **그때 무엇을 포기했는지**를 남긴다.

문서 본문(`requirements.md` 등)은 "무엇이 정해졌는가"만 서술한다.
"왜 그렇게 정했는가"는 여기에 있다. 나중에 그 결정을 뒤집으려는 사람이
같은 논의를 처음부터 반복하지 않게 하는 게 목적이다.

## 언제 ADR을 쓰나

**되돌리는 데 비용이 드는 선택**을 했을 때 쓴다.

| 쓴다 | 쓰지 않는다 |
|---|---|
| 여러 API·모듈에 걸치는 규칙을 정할 때 | 함수 하나의 구현 방식 |
| 라이브러리나 저장소를 고를 때 | 변수명, 파일 위치 |
| 나중에 바꾸면 마이그레이션이 필요할 때 | 이미 규약에 있는 내용을 따를 때 |
| 명백해 보이는 대안을 일부러 버렸을 때 | 되돌리는 데 비용이 없는 선택 |

애매하면 이렇게 판단한다.
**"6개월 뒤 누군가 이걸 보고 왜 이렇게 했냐고 물을 것 같은가?"**

## 상태

| 상태 | 의미 |
|---|---|
| 제안됨 | 논의 중 |
| 수용됨 | 적용 중 |
| 폐기됨 | 채택하지 않음 |
| 대체됨 | 다른 ADR이 이 결정을 뒤집음. 대체한 ADR 번호를 적는다 |

**기존 ADR은 수정하지 않는다.** 결정이 바뀌면 새 ADR을 쓰고 옛 것을 `대체됨`으로 바꾼다.
결정의 역사가 남아야 왜 돌아왔는지 알 수 있다.

## 쓰는 법

번호는 이어서 붙이고 파일명은 `NNNN-제목-슬러그.md`로 한다.
[_template.md](./_template.md)를 복사해서 시작한다.

**"고려한 대안"을 비워두지 않는다.** 그 칸이 ADR의 핵심이다.
대안 없이 내린 결정은 대개 결정이 아니라 습관이다.
