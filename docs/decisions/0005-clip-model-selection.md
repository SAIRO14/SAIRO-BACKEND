# 0005. CLIP ViT-B/32 임베딩 모델 선택

- **상태:** 수용됨
- **날짜:** 2026-07-23
- **관련:** 이슈 #39

## 맥락

사용자가 선택한 사진들로부터 취향 프로필(임베딩 벡터)을 생성하고, DB에 저장된 약 2,200장의 여행 사진과 유사도를 비교해 여행지를 추천해야 한다. 이를 위해 이미지를 고정 차원의 벡터로 변환하는 멀티모달 임베딩 모델이 필요했다.

## 결정

OpenAI의 `openai/clip-vit-base-patch32` (CLIP ViT-B/32) 모델을 사용한다. 출력 차원은 512이며, 이미지와 텍스트를 동일한 임베딩 공간에서 표현한다.

## 고려한 대안

| 대안 | 장점 | 버린 이유 |
|---|---|---|
| CLIP ViT-L/14 | 정확도 더 높음, 768차원 | 모델 크기 대비 취향 분석 품질 향상 미미, 추론 속도 느림 |
| BLIP / BLIP-2 | 이미지 캡셔닝 강점 | 분위기 유사도 비교보다 캡셔닝 최적화, 운영 복잡도 증가 |
| ResNet / EfficientNet | 경량, 빠름 | 텍스트 공간 공유 없음, 멀티모달 확장 불가 |
| 자체 파인튜닝 모델 | 도메인 특화 가능 | 학습 데이터·인프라 없음, MVP 범위 초과 |

## 결과

- 좋아지는 것: 사전 학습된 범용 시각 표현으로 추가 학습 없이 분위기 유사도 비교 가능, Hugging Face로 간단히 로드
- 나빠지거나 감수하는 것: 한국 여행 사진 도메인에 특화되지 않아 분위기 구분 정밀도가 파인튜닝 모델보다 낮을 수 있음
- 이 결정에 뒤따라야 하는 작업: DB 사진 2,200장 전체에 CLIP 임베딩 사전 생성 후 pgvector에 저장

## 다시 검토해야 할 시점

- 취향 분석 결과와 실제 선호 여행지 간 불일치율이 높게 나타날 때
- 한국 여행 도메인 특화 모델이 공개될 때
