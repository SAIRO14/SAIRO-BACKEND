# 0009. 한국관광공사 TourAPI contentTypeId=25 큐레이션 코스 데이터

- **상태:** 수용됨
- **날짜:** 2026-07-23
- **관련:** 이슈 #39, PRD §8

## 맥락

1박 2일 큐레이션 코스를 제공하려면 지역별로 검증된 여행 코스 데이터가 필요하다. MVP 기준 7개 지역, 지역당 3개 코스를 제공한다.

## 결정

한국관광공사 TourAPI KorService2의 `contentTypeId=25` (여행 코스) 데이터를 실시간으로 호출해 사용한다. 코스 목록은 `areaBasedList2`, 코스 내 스팟은 `detailInfo2`, 좌표는 `detailCommon2`로 조회한다.

## 고려한 대안

| 대안 | 장점 | 버린 이유 |
|---|---|---|
| 자체 DB에 코스 데이터 직접 입력 | 외부 의존성 없음, 응답 빠름 | 데이터 수집·유지보수 비용 높음, MVP 속도 저하 |
| 네이버 지도 / 카카오맵 API | 풍부한 POI | 여행 코스 단위 데이터 없음, 라이선스 비용 |
| 여행 블로그 크롤링 | 실제 사용자 경험 반영 | 저작권 이슈, 데이터 품질 불안정 |

## 결과

- 좋아지는 것: 공공 데이터로 라이선스 문제 없음, 관광공사가 편집한 검증된 코스, 빠른 MVP 구현
- 나빠지거나 감수하는 것: 외부 API 장애 시 코스 기능 전체 불가 (빈 응답 반환으로 부분 장애 처리), API 응답 스펙 변경 시 파싱 코드 수정 필요, 실시간 호출로 응답 지연 발생 가능
- 이 결정에 뒤따라야 하는 작업: 외부 API 타임아웃 설정, 장애 시 graceful degradation 처리

## 다시 검토해야 할 시점

- TourAPI 안정성 문제가 반복될 때 → 캐싱 또는 자체 DB 이전 검토
- 지원 지역을 7개 이상으로 확장할 때
