# 0007. 익명 기기 ID (X-Device-Id) 인증 방식

- **상태:** 수용됨
- **날짜:** 2026-07-23
- **관련:** 이슈 #39, PRD §9

## 맥락

SAIRO는 회원가입 없이 서비스를 제공하는 것이 핵심 UX 원칙이다. 그러나 취향 분석 이력과 저장 코스 이력을 기기 단위로 유지하려면 최소한의 식별자가 필요하다.

## 결정

앱 최초 실행 시 클라이언트가 UUID v4를 생성해 기기에 저장하고, 이후 모든 API 요청에 `X-Device-Id` 헤더로 전달한다. 서버는 이 값을 식별자로만 사용하며 개인 식별 정보를 수집하지 않는다.

## 고려한 대안

| 대안 | 장점 | 버린 이유 |
|---|---|---|
| 소셜 로그인 (카카오·애플) | 기기 교체 시 이력 유지, 강한 식별 | 회원가입 없는 UX 원칙 위반, MVP 범위 초과 |
| 서버 발급 세션 토큰 | 서버 제어 가능 | 클라이언트 생성 UUID와 실질적 차이 없음, 추가 API 필요 |
| 기기 고유 식별자 (IDFA 등) | 안정적 식별 | 플랫폼 정책 제한, 개인정보 수집 이슈 |

## 결과

- 좋아지는 것: 회원가입 없이 이력 관리 가능, 개인 식별 정보 수집 없음, 구현 단순
- 나빠지거나 감수하는 것: 앱 재설치 시 이력 초기화 (의도된 트레이드오프), 기기 ID 탈취 시 다른 사용자의 이력 접근 가능 — 민감 데이터가 없으므로 허용
- 이 결정에 뒤따라야 하는 작업: 없음 (현재 구현 완료)

## 다시 검토해야 할 시점

- 회원가입 기능을 도입할 때
- 기기 ID 기반 어뷰징이 발생할 때
