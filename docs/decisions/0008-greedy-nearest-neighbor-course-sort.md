# 0008. Greedy Nearest-Neighbor 코스 정렬

- **상태:** 수용됨
- **날짜:** 2026-07-23
- **관련:** 이슈 #39

## 맥락

사용자가 선택한 스팟 목록을 1박 2일 코스로 구성할 때 이동 거리를 최소화하는 순서로 정렬해야 한다. 스팟 수는 통상 4~12개 수준이다.

## 결정

Greedy Nearest-Neighbor 알고리즘을 사용한다. 첫 번째 스팟에서 시작해 매 단계에서 아직 방문하지 않은 스팟 중 가장 가까운 것을 선택한다. 좌표가 없는 스팟은 후순위로 배치한다.

## 고려한 대안

| 대안 | 장점 | 버린 이유 |
|---|---|---|
| 정확한 TSP (완전 탐색) | 최적 경로 보장 | 스팟 수 증가 시 O(n!) 복잡도, 실용적이지 않음 |
| OR-Tools / 외부 경로 최적화 | 높은 품질 | 외부 의존성 추가, MVP 범위 초과 |
| 사용자 수동 정렬 | 사용자 제어 | UX 복잡도 증가, 자동 정렬이 핵심 가치 |
| 랜덤 순서 | 구현 단순 | 이동 동선 비효율로 UX 저하 |

## 결과

- 좋아지는 것: 구현 단순 O(n²), 4~12개 스팟 범위에서 충분히 합리적인 경로 생성
- 나빠지거나 감수하는 것: 시작 스팟 선택에 따라 결과가 달라질 수 있음, 최적 경로 보장 안 됨
- 이 결정에 뒤따라야 하는 작업: 시작 스팟을 명시적 기준(예: 가장 북쪽)으로 고정해 결정적(deterministic) 결과 보장 필요 — 현재 `findAllById()` 반환 순서에 의존 중 (open-questions.md 참조)

## 다시 검토해야 할 시점

- 코스 스팟 수가 15개 이상으로 늘어날 때
- 이동 동선 품질에 대한 사용자 불만이 생길 때
